# Revenue Decision Framework — 判断OS

制定: 2026-09-10。数値の閾値・時間枠は運用上の仮置きであり、売上予測/業界ベンチマークではない。

## 1. タスクの選び方

最上位の問いは「追加費用を極力かけず、日次5,000〜10,000円への到達確率を上げるか」。まず安全・権限・根拠・読者適合をゲートにする。ゲート不合格を高報酬や総合点で相殺しない。

タスク票は `目的 / 根拠 / 仮説 / 下表7軸 / 対象ファイル / 非対象 / 担当モデル / 時間枠 / 完了条件 / 評価期限 / 人間依存 / 撤回方法` を記録。入力不足はunknownと必要な確認を明記する。

| 軸 | 評価の目安 | 必要な説明 |
| --- | --- | --- |
| Revenue Impact | 0=経路なし、1=流入のみ、2=CV経路/計測の障害解消、3=実績あるCV/収益改善 | どのページ→商品→成果地点に効くか。未実績案件を3にしない |
| Time to Revenue | 短=7日以内、中=8〜30日、長=31日以上、unknown | 開発時間でなく初CV/確定までの暦日。審査待ちを含む。学習までの日数も別記 |
| Cost | 追加支出0円を基本。作業時間1h/4h/1日超を併記 | 支出、API/利用枠、保守時間。支出が必要なら人間へ |
| Evidence / Data Confidence | E0=仮説、E1=公開一次情報、E2=自サイト実測、E3=成熟した確定成果と反復 | 案件条件はE1でもCVRはE0。同じラベルで全項目を保証しない |
| Automation Potential | 低=判断中心、中=部分定型、高=同じ手順を反復 | 反復回数と削減時間の実測前は自動化を先行しない |
| Risk | 低=局所文書、中=収益表示/計測変更、高=安全/規約/外部変更 | 誤誘導・過剰訴求・情報流出・計測汚染・依存関係を含む |
| Expected Learning Value | 0=意思決定不変、1=記述改善、2=対象/訴求を絞れる、3=採用/停止を判断できる | 何を観測し、どうなれば続行/変更/停止するか |

実績前は「安全上の必須修正 → 短期間に学習2〜3が得られるタスク → CV経路の障害解消」を優先。似た候補なら短時間・0円・可逆な方を選ぶ。根拠のない重み付き期待売上ランキングは作らない。EPCが信頼できる段階で実績による比較へ切り替える。

適用例（作業時間も仮置き）:

| 候補 | Impact / 初収益まで | Cost | Evidence | Automation | Risk | Learning | 判断 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 3案件の適格性＋既存X集計の照合 | 2 / unknown、学習1〜2日 | 0円、2h | E1、需要E0 | 低 | 低※公開調査 | 3 | 最優先 |
| 欠損を0にする集計の是正 | 2 / unknown、学習は実測後 | 0円、4h | コード確認、成果E0 | 高 | 中 | 3 | データ投入前に必須 |
| 全サービスの自動更新基盤 | 1 / unknown | 0円でも1日超 | E1、収益E0 | 高 | 中 | 1 | 延期 |
| 全面リデザイン | 0 / unknown | 1日超 | E0 | 低 | 中 | 0 | 採用しない |

## 2. 何を検証するか

Synthesiaは最初の**制度確認候補**として妥当だが、販売優勝候補としては未実証。公式は対象支払い25%・60日Cookieを案内するが、無料登録=報酬CVではなく、最大額は平均単価ではない。日本での参加、読者需要、承認率、実入金単価は別確認。[公式制度](https://www.synthesia.io/partners/affiliates)

Adobeは既存画像コンテンツとの接続を検証しやすい対抗。対象プランの有効購入が成果であり、trial/cancelled等は報酬対象外。Fireflyを説明したから任意のAdobe製品へ誘導してよいわけではない。[公式制度・対象商品](https://www.adobe.com/affiliates.html)

Canvaは一般制作用途という需要仮説の比較対象。既存台帳の海外言語affiliate解説だけでは現行日本向け参加条件を確定できないため収益計算はunknown。知名度・フォロワー適合を実測扱いしない。

当面はSynthesia/Adobe/Canvaの**条件・読者用途の調査だけ並行**し、2時間程度で比較票を作る。ASP案件は追加最大3件まで。販売実験は条件がそろう1案件、次点1件を待機。3案件同時の薄い流量A/Bテスト、審査待ちのCanva/Leonardoに開発を合わせることは避ける。既存ASPで承認済みの適合案件があれば、公開報酬が高い未承認案件より先に検証してよい。選定変更はDECISIONSへ。

## 3. A8等で人間が探す案件

以下は検索方針であり、管理画面の正確なメニュー名・案件存在・報酬条件を確認した記録ではない。今回ログイン・申請・スクレイピングは行わない。

| 検索カテゴリの目安（近い画面分類を選ぶ） | 検索キーワード | 想定経路 |
| --- | --- | --- |
| ソフトウェア・業務支援・インターネット | AI、生成AI、SaaS、議事録、文字起こし、翻訳、資料作成 | 業務の困りごと→用途比較→無料申込/有料プラン |
| デザイン・動画・クリエイター支援 | 画像編集、動画編集、アバター、デザイン、Adobe、Canva | 画像/動画記事→対応する製品→試用後購入 |
| 学習・資格・スクール | AI講座、生成AI講座、リスキリング、プログラミング、データ分析 | 学び方記事→内容/対象者/総費用確認→相談/受講 |

検索は既存提携済み→新規候補の順。学習案件は現時点の掲載記事との適合を別確認し、画像比較から高額スクールへ無関係に誘導しない。

**最低条件（掲載前の必須ゲート）**:

- 日本ユーザーが実際に申込可能で、対象者・商品・成果地点・報酬単位/通貨・主要否認条件が明確。未知なら候補保留、勝手に補完しない。
- aierabiの記事テーマとX読者の課題を1文で結べる。LPがスマホで読め、価格・契約/解約・申込手順を確認できる。
- サイト掲載、SNS利用、X直接広告、X→記事送客、`/go`等の中間遷移、追加計測パラメータの可否を**別項目**で確認。SNS可だけでXやリンク改変を許可と解釈しない。
- 初期検証のために運営者が有料契約/自己購入する必要がない。高額成約のみ・長期商談のみは初回候補から原則外す。
- 人間が媒体登録/提携状態・規約・広告表示を確認。規約が不明/矛盾なら広告有効化を止める。

**優先条件（実績ではなく探索用の目安）**:

- 無料申込で成果確定する案件は1CV 1,000円以上、有料購入は3,000円以上をまず探す。ただし適合・確定率・CV地点を報酬より優先し、少額でも既存承認/需要根拠が強ければ比較に残す。
- カード不要の無料申込、短い入力、明確な価値、認知あるブランド、日本語LP。無料登録後の有料化が成果なら摩擦を二段階で評価。
- 承認率/EPCが取得できる案件。ただし期間・件数・媒体母集団の異なるASP全体EPCは自サイト予測ではない。
- 確定目安30日以内、再訪期間30日以上は比較時の加点目安。実際は案件条件を優先し短期案件を機械的除外しない。継続報酬は対象期間・解約/返金/上限まで明示される場合のみ加点。

**除外条件**: セルフバック限定、自己申込の偽装、誇大な稼げる保証、投機/ギャンブル/医療等の高リスク領域、SNS禁止なのにX流入へ依存する案件、不明な事業者/LP、商標誤認、過剰な個人情報収集、見えない契約費用、既存読者と無関係な高額案件。セルフバックは紹介収益/継続需要の証拠に算入しない。

### 公開情報と会員限定情報の境界

- `data/official-sources.json` / service-factsには公開一次情報のみ。会員ページURL・帳票・限定報酬/承認率を混ぜない。
- ASPの画面/原本/契約条件は人間が指定するリポジトリ外の非公開保管先で管理。保存先を勝手に新設せず、ブラウザやcredentialを操作しない。
- このrepoのdocsには公開根拠と「人間確認待ち」だけ。内部案件IDの代わりに非識別の案件aliasを使用。原本の内容は共有許可・再配布条件確認後だけ分析する。
- 生の成果注文、メール、IP、アカウントID、銀行/税務情報は取込不可。匿名集計でも営業上非公開ならGitに入れず、今後のT3でユーザー指定のローカル入力を扱う。既存importsは空の見本を維持。
- affiliate-configはクライアントにも含まれる。非公開条件は入れない。公開用広告URLも媒体条件/公開可否を人間確認してから別タスクで扱う。

## 4. 最小計測契約（設計。未実装部分はT3）

指標の優先順位は **売上 → CV → EPC → affiliate click → CTA CTR → サイト流入**。上位指標が欠損なら下位指標で学習するが、収益成功とは呼ばない。

- 売上=確定した紹介料（返品/取消反映後）。発生見込、確定、入金を別列。商品購入額と紹介料を混同しない。
- CV=同じ観測期間/帰属群の確定件数。発生CV/否認CVも別列で保持。件数が確認できないならnull。
- EPC=同じ帰属群の確定紹介料÷affiliate click。ASP clickと自サイトredirect eventの分母は混ぜず別名で表示。通貨換算の根拠なしにJPY化しない。
- CTA CTR=CTAクリック÷CTA表示回数。同じページ/位置で集計。現実装には表示計測なし。暫定のクリック÷ページセッションは「session CTA rate」と別名にしCTRと呼ばない。
- 投稿リンクCTR=投稿リンククリック÷投稿imp。サイトセッションは別段階。クリックイベントはユーザー数ではない。

将来の集計キーは `date/cohort_window, source_page, service_id, post_id, campaign_id, cta_type, cta_position, environment`。source/page/service/post等は許可リストの固定編集ID。自由クエリ、個人ID、fingerprintを送らない。timestampは実時刻、集計のタイムゾーンはJSTに固定。

Xリンクは `utm_source=x, utm_medium=social, utm_campaign=<固定実験ID>, utm_content=<固定投稿ID>` を候補にする。サイトからgoまで固定IDを保持する実装とテストが必要。ASPが許可した集計用subID等にページ/投稿/サービスの組合せaliasを渡せ、成果exportに戻る場合だけCVを帰属。勝手に広告URLへパラメータを足さない。非対応ならサービス単位まで、ページ/投稿別CV/EPCはunknown。クリック比で売上を按分しない。

取り込み前に `期間/通貨/粒度/集計定義/成熟期限/取得元/重複バッチ/欠損` を検証。片側データ欠損はnull、分母0の率はnull、検証済み観測0のみ0。page sessionsをservice行ごとに重複加算しない。by_page/by_post/by_serviceの各集計と全体を突合し、非帰属分はunknownの行に残す。

ローカル検証はgtag/遷移をモックにし本番Analytics/ASPに送らない。通常リンククリックと中間ページ再訪を分離し、計測失敗で遷移を壊さない設計をレビュー。GA標準送信・同意・開発環境無効化を確認するまで「PIIゼロ」と表明しない。

## 5. 自律改善ループとXの使いどき

1. **収集**: 人間が共有可能な直近20〜30投稿/28日程度のX集計、ページ集計、案件条件を取り出す。取れない指標はunknown。毎回全サイトを調査しない。
2. **検出**: 欠損/帰属不明/成熟前かを最初に判定。低CVが需要不足か、提携未承認か、送信欠損かを分ける。
3. **仮説**: 実験ID、対象読者/1ページ/1案件、1つの変更、比較期間、観測数/期限、継続・停止基準をDECISIONSに事前記録。
4. **実装**: NEXT_TASKSの1件だけ。小さい差分と取り消し手順。UIは「結論直後の文脈CTA」「スマホ要約」等、CTR/CV仮説がある場合のみ。
5. **テスト**: 形式/境界値/広告表示/非送信/関連性/モバイル確認、npm run check。人間が公開/投稿可否を判断。合格だけで自動公開しない。
6. **計測**: 承認後に人間が少量投稿。初回は7〜14日・最大6投稿を目安に、同じ訴求の連投を避ける。2 Reach、1 Authority（実測主張なし）、2 Conversion、1 Retentionから対象用途に合わせ選ぶ。約6,000人全員への到達を前提にしない。
7. **評価**: 週次レビューを手動で行う（スケジュール登録なし）。14日または100 affiliate clicksを暫定の見直し点とするが、統計的有意/成否の保証ではない。CVは案件の承認/返品期間が成熟するまで保留。流量不足なら期間延長または1仮説だけ変更。0CVを即失敗にしない。
8. **次へ**: matureな確定収益/EPCを主軸に継続・改善・停止を記録。規約違反懸念/誤情報/誤遷移/計測汚染が見つかれば新規流入を止める判断を人間へ即提示。安全なローカル調査は継続。

Xは全更新基盤の完成待ちにしない。既存投稿データの分析は今から可能。公開済み誘導先の事実確認・最小計測・媒体条件・人間の投稿承認がそろった最初の時点で小さく使う。提携前なら無料の用途調査/記事送客を学習実験として分離できるが、今回の実投稿禁止は継続。Authorityの既存得点や「検証した」体験談を根拠なしに使わない。

安定収益の判定は単発CVでなく、少なくとも成熟した28日コホートを複数回比較し、日平均紹介料・日々の変動・否認/返品・投稿/保守時間・案件依存を確認する。将来収益の保証にはしない。日次目標の感度計算は `紹介料=imp×投稿リンクCTR×サイトからのaffiliate遷移率×発生CVR×確定率×確定CV単価`。各段階の分母をそろえ、継続報酬は実観測分のみ計上。旧レポートの仮定50〜200 click/日が得られる証拠はまだない。

## 6. モデル分担と人間承認

ユーザー指定の分担を採用。[OpenAI公式モデル案内](https://developers.openai.com/api/docs/models) のAstra=複雑な推論、Terra=能力/コストのバランス、Luna=コスト重視という位置づけとも整合する。API単価をこのアカウントの実費とみなさず、モデル設定/契約を勝手に変更しない。

| 担当 | 任せる仕事 | 受け渡し/完了条件 |
| --- | --- | --- |
| GPT-6 Astra | 戦略、案件優先度の大幅変更、計測の帰属設計、大規模設計、重大レビュー | 選択肢/根拠/反証条件/安全境界をDECISIONSへ。常時呼ばない |
| Terra | 既存契約に沿う通常実装、根拠付き事実更新、中程度の仮説評価、局所レビュー | 1タスク、指定ファイル、境界テスト、check、状態更新。推測補完しない |
| Luna等 | 根拠と転記先が確定したJSON追加、定型整理、意味を変えないlint修正、文書同期 | 入出力見本と検証条件必須。意味/出典が曖昧ならTerraへ |
| 人間 | 外部権限・契約・公開/投稿、非公開帳票管理、重大変更の承認 | 行為/対象/範囲を個別判断。モデルの承認を代用しない |

委任票: `タスクID / 仮説 / 入力根拠 / 許可ファイル / 触らないもの / 完了条件 / 実行禁止 / 相談条件`。戻り値: `変更 / 証拠 / テスト結果 / unknown / 人間依存 / 次の1手`。モデル数を増やすこと自体はしない。今回は新エージェント/新タスクを起動しない。

**エスカレーション**:

- Luna→Terra: 出典/値/単位の不一致、定型を超えるロジック変更、2回の修正でも同じテスト不合格。推測で通さない。
- Terra→Astra: 複数レイヤーの帰属/スキーマ変更、主要案件の入替に判断が割れる、成熟した2回の実験でも改善根拠なし、1営業日を超える新基盤が必要、指標が矛盾して原因を切り分けられない。
- 全モデル→人間（必要ならAstraもレビュー）: 支出/登録/申請/規約同意/credential/銀行/税務/main merge/deploy/DNS/外部アカウント/SNS、ランキング評価ロジック重大変更、重大セキュリティ変更。権限を得るまで当該操作を停止。規約やプライバシーが曖昧なら同じく停止し、専門的確認が必要と伝える。
- 相談時は「事実・試したこと・選択肢・推奨・不足する承認」の5点だけを添える。BLOCKEDのない独立したローカル作業まで止めない。
