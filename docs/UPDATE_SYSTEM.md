# 更新システムの現状とMVP

## 停止原因

`changes.json` の最終更新日は 2026-03-31 ですが、更新を起動・収集・検証・反映するスクリプトはありません。モデル、テスト、安全性、カテゴリ、記事、サイト内の年月バッジを人手で別々に更新する構成です。そのため、1か所を更新しても表示値・OGP・記事・sitemap の整合性を自動で保てません。

## 現在の工程

1. 公式情報を人が確認する（未実装の外部収集）。
2. 人が `models.json`、カテゴリJSON、記事JSON、`changes.json` を編集する。
3. 人がスコアの再テスト・採点・ランキング計算を行う。
4. `npm run build` が sitemap を再生成する。
5. 人がレビューし、別途本番へ反映する。

## 自動化の境界

自動化してよいのは、公式情報の**候補**取得、差分候補、コンテンツ草案、検証、承認待ちキューへの保存です。ランキング・安全性の点数、料金、提供可否を根拠なしに書き換える自動処理は作りません。

## 追加したMVP

`data/content-queue/` は生成物を保存するだけの承認待ちキューです。SNSへの投稿、サイト公開、データ更新を行いません。各候補には確認要否と必要な一次情報を残します。

## 現在の位置づけ

フェーズ1では公式台帳23件、service-facts 16件、validatorを追加済み。自動取得・承認パッチ・raw評価集計は未実装です。将来案はCONTINUOUS_UPDATE_PLAN、現状はPROJECT_STATE、実行順はNEXT_TASKSを参照し、この文書から別のタスク順を作らないでください。
