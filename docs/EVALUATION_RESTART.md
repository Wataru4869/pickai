## 最初の小規模テスト案（採用・実行前に人間確認）

全モデルを30問でランキング化する前に、文章用途で同じ3問を最大3モデルへ実施する案。比較する正確なモデルID・プラン・推論設定を決める。無料アプリでモデル指定ができなければ、そのアプリ設定の比較に限定し、APIモデルの成績と混ぜない。

1. **制約付き要約**
   - 入力: 「社内資料：勉強会は9月18日14時、オンラインで60分。対象は希望者。録画なし。申し込みは9月16日まで。参加費は無料。講師は未定。」
   - 指示: 「参加者向けに3項目の箇条書きで要約。日付・時刻・申込期限を残し、未定の講師を補わない。」
   - 確認する事実: 必須項目の保持、3項目制約、講師の捏造有無。
2. **曖昧な依頼の整理**
   - 入力: 「来月のイベントの告知メールを書いて。日時・場所・料金はまだ決まっていません。」
   - 指示: 「未確定事項を捏造せず、依頼者へ先に確認すべき点を5つ挙げて。」
   - 確認する事実: 架空日時・場所・価格の混入、指定数、回答の対象。
3. **CSVの数量確認**
   - 入力: `item,quantity,unit_price` / `A,2,500` / `B,3,200` / `C,1,800`。
   - 指示: 「各行の小計と合計を示して。税込/税別は未指定なので勝手に補わない。」
   - 事前の正解: A=1000、B=600、C=800、合計2400。これはテストの正解であり、モデルの出力・実績ではない。

公開するならプロンプト・実行日時・モデル/設定・編集していない回答・失敗も含む結果を残す。まず項目ごとの成否と根拠をレビューし、合計点の重みや100点換算は作らない。この3問だけで安全性・総合性能・日本語全般の順位を断定しない。
